# 設計判断記録 (ADR)

設計判断、採用理由、変更履歴を記録する。新しいエントリは末尾に追加する（古い順）。

## 記録フォーマット

```
## D-XXX: タイトル

- 日付: YYYY-MM-DD
- 状態: 採用 / 却下 / 廃止（廃止の場合は後継のDを記載）

### 背景
- なぜこの判断が必要になったか

### 決定
- 何を決定したか

### 理由
- なぜその選択をしたか（検討した代替案があれば併記）

### 影響
- この決定が及ぼす影響、制約
```

## D-001: 技術スタックはWeb技術（React + TypeScript + Vite）+ Capacitorを採用する

- 日付: 2026-08-06
- 状態: 採用

### 背景
- 「どこでもプレゼン」はAndroid APK配布を最終目標としつつ、開発中はPWA/Web版でよいという要件があった。開発コンテナにはNode.js（node22）・JDK 21・Gradle 8.14.3はあるが、Android SDK・Flutter SDK・エミュレータ/実機は存在しない。

### 決定
- React + TypeScript + Viteでフロントエンドを実装し、Phase 4でCapacitorを導入してAndroid APK化する。状態管理ライブラリ・ルーターは追加せず、`useReducer`とHistory APIで画面遷移を実装する。CSSは素のCSS＋カスタムプロパティ（デザイントークン）とし、Tailwind等は導入しない。

### 理由
- Flutterは却下: SDK未導入で導入コストが大きく、「開発中はPWA/Web版でよい」という要件とも合わない。自動レイアウトエンジンの本質はテキスト計測と矩形配置の純粋計算であり、DOM/Canvasを持つWebの方が実装・検証コストが低い。
- Capacitorは採用: 開発したWebビルド成果物をそのままAndroid WebViewに載せられ、Phase 1〜3を純Webとして進め、Phase 4で`npx cap add android`するだけでAPK化できる。導入済みのJDK 21/Gradle 8.14.3がCapacitor 8のAndroid要件と一致する。
- 状態管理ライブラリ・ルーターは画面数（3画面）と単一ドキュメント編集という要件規模に対して過剰な抽象化になるため見送った（判定ラダー1: そもそも必要か）。

### 影響
- `npm install`はNode 22系（`/opt/node22`）を使う必要がある（Vite 8のengines要件）。
- Phase 4でAndroid SDKの追加導入が必要。実機・エミュレータがこの開発コンテナにないため、debug APKのビルド成功とビルド手順書の整備をPhase 4の完了条件とし、実機での動作確認はUser側で行う。

## D-002: 自動レイアウトエンジンをレンダラ非依存の純粋関数として設計する

- 日付: 2026-08-06
- 状態: 採用

### 背景
- 自動レイアウトは本アプリ最大の特徴機能であり、編集画面のライブプレビュー・プレゼン画面・PNG/PDF出力の3箇所で同じ結果を再現する必要がある。

### 決定
- `layoutSlide(slide, measurer): LayoutResult`という純粋関数を`src/layout/`に実装する。入力テキストの解析（`parse.ts`）→重要度付与（`analyze.ts`）→テンプレート選択（`templates.ts`）→文字計測・配置（`measure.ts`/`layout.ts`）の順に処理し、出力は1280×720の仮想座標系における絶対配置ボックス列（`LayoutResult`）とする。DOM/Canvas双方のレンダラはこの同じ`LayoutResult`を描画するだけとし、レイアウト判断ロジックを二重実装しない。
- AI補助機能（タイトル推定・優先順位判定・レイアウト最適化・文字量警告・文章要約・読みやすさ評価）は、オフラインファースト要件を優先し、外部LLM APIを呼ばずルールベース/ローカル処理（キーワード辞書・文字数・行数等の統計）で実装する。

### 理由
- レンダラ非依存にすることで、`html2canvas`系ライブラリ（日本語フォント埋め込みで壊れやすい）が不要になり、PNG/PDF出力とプレビューの見た目のズレを構造的に防げる。文字計測を`TextMeasurer`インタフェースで注入することで、エンジン自体をDOMなしでユニットテストできる。
- 外部LLM API連携は将来`analyze`の結果を差し替える形で拡張できる余地を残すが、今回はインタフェースを先回りして作らない（YAGNI）。

### 影響
- 新規スライドテンプレート（2カラム・画像レイアウト等）の追加は`templates.ts`の変更のみで完結する。
- Phase 2のCanvasレンダラ・PDF出力は`LayoutResult`をそのまま消費するだけで、レイアウト判断の再実装は発生しない。
